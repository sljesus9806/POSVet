Instalar Ligerito en una PC con Windows POS

Instructivo paso a paso · una sola PC con Windows (la PC es el servidor) · v2 — 2026-06-10
💡 Para guardar este instructivo como PDF Abre este archivo en Google Chrome y pulsa Ctrl + P → en Destino elige “Guardar como PDF” → Guardar. (El PDF de la carpeta se genera así; si editas este HTML, vuelve a generarlo.)
Cómo funciona, en una frase Una sola computadora con Windows hace de servidor; la persona que la usa entra con Google Chrome a http://localhost:3000. Sin Docker, sin internet en el día a día, sin ventanas raras. Solo la instalación necesita internet.
🛠️ Quien instala (tú, una sola vez): hace las Fases 1 a 4 de abajo. Necesita la PC Linux con la llave de licencia y un rato con internet en la PC del cliente.
🧑‍💼 Quien lo usa (el cliente, todos los días): solo prende la compu y abre Chrome. Ve la sección “Uso diario”.
Contenido: Fase 1 — En Linux: preparar la licencia · Fase 2 — Armar el paquete (USB) · Fase 3 — Instalar en la PC del cliente · Fase 4 — Primer arranque · Uso diario · Respaldos · Mantenimiento · Solución de problemas
⚠️ Lo único que NO puede faltar: el token de licencia La app tiene candado: sin licencia.token se queda bloqueada en la pantalla /licencia y no deja entrar. El token se emite en tu PC Linux (la que tiene la llave privada) y solo viajas con el token al cliente. Nunca lleves la llave privada a la PC del cliente.
✅ Antes de salir hacia el cliente, lleva listo:
  • El ZIP del proyecto (Fase 2) y tu archivo licencia.token (Fase 1) en un USB.
  • Decidido el nombre del negocio (va dentro del token) y la contraseña del usuario postgres que usarás.
  • Que la PC del cliente tendrá internet durante la instalación (después ya no).

1En tu PC Linux — preparar la licencia

  1. Entra al repo y trae lo último de main (ahí ya están todos los arreglos del instalador de Windows): 
    cd ~/POSVet        # o donde lo tengas
git checkout main && git pull
  2. Comprueba que tienes la llave privada correcta (la que empareja con la pública que la app valida en keys.ts): 
    openssl pkey -in .licencia/private.pem -pubout -outform DER | base64 -w0
    El resultado debe ser exactamente: 
    MCowBQYDK2VwAyEAsXfC9xDWowQjrKTIltQk4SV6ttc9TRwBKhhO/rlIwlM=
    Si no coincide Usa la llave real del repo de licencias: ~/posvet-licencias/.licencia/private.pem (también empareja). Nunca corras lic:keygen ni cambies keys.ts: invalidaría a todos los clientes y tokens ya emitidos.
  3. Emite el token offline de larga duración a nombre del negocio del cliente (--meses 120 = 10 años): 
    npm run lic:emitir -- --cliente "NOMBRE DEL NEGOCIO" --modo offline --meses 120
    El comando imprime el token y lo guarda en .licencia/emitidas/.
  4. Copia ese token a un archivo llamado licencia.token (lo necesitarás en la Fase 3). Por ejemplo, tomando el último emitido: 
    cp .licencia/emitidas/$(ls -t .licencia/emitidas/*.lic | head -1 | xargs basename) /tmp/licencia.token
Por qué offline y 10 años El cliente trabaja sin internet; una licencia offline perpetua-renovable evita que se bloquee sola. La identidad “Licenciado a: NOMBRE DEL NEGOCIO” queda visible dentro de la app.

2Armar el paquete para el cliente (USB)

Llevas el código + el token, pero ni node_modules, ni la llave privada, ni .env (todo eso se genera en la PC del cliente). Desde Linux, exporta solo lo versionado de main:

cd ~/POSVet
git archive --format=zip --output=/tmp/ligerito-cliente.zip main

Copia al USB dos cosas: ese ligerito-cliente.zip y tu licencia.token.

Por qué con git archive Genera un ZIP limpio (sin node_modules, sin .licencia, sin .env) y no tienes que iniciar sesión en GitHub desde la PC del cliente. El motor de la base de datos (Prisma) es por sistema operativo, por eso la app se construye en Windows durante la instalación y no se puede mandar ya compilada desde Linux.

3Instalar en la PC del cliente (Windows)

Requisitos

  • Windows 10 u 11 (ya traen winget, el instalador de apps de Microsoft).
  • Internet — solo durante la instalación. El uso diario es 100% sin conexión.
  • PostgreSQL: el instalador lo pone solo con winget (versión 17). Si prefieres control, instálalo tú antes desde postgresql.org/download/windows y anota la contraseña del usuario postgres que definas — la pedirá el instalador.
  • Node.js: lo instala el script solo si falta. No tienes que hacer nada.

Pasos

  1. Descomprime el ZIP en una ruta simple, por ejemplo C:\Ligerito. (Clic derecho en el ZIP → Extraer todo → escribe C:\Ligerito.)
  2. Copia tu licencia.token del USB a esta ruta exacta: 
    C:\Ligerito\deploy\windows\licencia.token
  3. Abre PowerShell como Administrador: botón Inicio → escribe powershell → clic derecho en Windows PowerShell → Ejecutar como administrador. (Administrador es necesario para instalar Node/PostgreSQL y programar los respaldos.)
  4. Entra a la carpeta y corre el instalador con la contraseña de postgres: 
    cd C:\Ligerito\deploy\windows
.\instalar.ps1 -PgSuperPassword "LA_CONTRASEÑA_DE_POSTGRES"
    Alternativa sin escribir comandos: en el Explorador, clic derecho en Instalar.bat → Ejecutar como administrador; te pedirá la contraseña oculta.
    ¿Otro puerto? Añade -Puerto 8080 (entonces el favorito sería localhost:8080). Por defecto es 3000.
  5. Espera unos minutos. El instalador hace todo solo, en este orden:
    • Instala Node y PostgreSQL si faltan, y deja el servicio de Postgres en arranque automático.
    • Crea la base de datos posvet y su usuario.
    • Genera el .env de producción (con una clave de sesión nueva).
    • Instala dependencias, migra y siembra datos, y construye la app.
    • Instala la licencia desde tu licencia.token.
    • Deja el arranque automático al iniciar sesión + un icono Ligerito en el Escritorio.
    • Programa el respaldo automático cada 30 min.
  6. Al terminar, se abre Chrome solo en http://localhost:3000. Sigue a la Fase 4.
El instalador es repetible Si algo se interrumpe (se cae el internet, contraseña equivocada, etc.), vuélvelo a correr: no rompe nada y retoma lo que falte. Conserva la base y el .env que ya existan.

4Primer arranque y configuración

  1. En Chrome, entra con el usuario de fábrica: admin@posvet.local / admin12345.
  2. Cambia la contraseña de inmediato en el menú Usuarios.
  3. En Configuración, escribe el nombre / razón social del negocio. (La marca de la app es “Ligerito”; el nombre del negocio se pone aquí y sale en tickets y reportes.)
  4. Confirma que no te manda a la pantalla /licencia. Si lo hace, ve a “Solución de problemas”.

Uso diario (para el cliente)

  • Prende la compu → el servidor arranca solo y abre la app en Chrome.
  • Si cierras la ventana: abre el icono Ligerito del Escritorio, o el favorito http://localhost:3000.
  • No hay que abrir terminales ni nada técnico.
  • Sugerencia: deja http://localhost:3000 en Favoritos de Chrome.
Reiniciar el servidor a mano (rara vez): doble clic en C:\Ligerito\deploy\windows\iniciar.ps1. Los errores quedan en C:\Ligerito\deploy\windows\logs\.

Respaldos automáticos (ya quedan configurados)

El instalador deja una Tarea Programada de Windows (Ligerito - Respaldo BD) que respalda la base cada 30 minutos, corra o no la app, mientras la PC esté prendida.

DatoValor
CarpetaC:\Ligerito-Respaldos
Formato.dump comprimido (pg_dump) · nombre posvet_AAAAMMDD_HHMMSS.dump
Retención7 días (los más viejos se borran solos)
BitácoraC:\Ligerito-Respaldos\respaldos.log
Respaldo a manopowershell -ExecutionPolicy Bypass -File respaldar.ps1
Recomendación de seguridad Los respaldos quedan en el MISMO disco de la PC. Copia de vez en cuando la carpeta C:\Ligerito-Respaldos a un USB o a la nube. Para mandarlos directo a otra unidad fija, reinstala con .\instalar.ps1 -RespaldoDestino "D:\Respaldos" -RespaldoDias 14.

Restaurar desde un respaldo (recuperación)

DESTRUCTIVO — reemplaza los datos actuales Úsalo solo para recuperar tras una pérdida, y cierra la app antes. 
cd C:\Ligerito\deploy\windows
.\restaurar.ps1 -Archivo "C:\Ligerito-Respaldos\posvet_20260610_120000.dump"

Te pide escribir SI para confirmar; al terminar, reinicia el servidor con iniciar.ps1.

Mantenimiento

Necesito…Cómo
Actualizar a una versión nueva del código Reemplaza los archivos del proyecto (descomprime el ZIP nuevo encima) y vuelve a correr Instalar.bat como administrador. Conserva la base y el .env.
Cambiar el puerto Reinstala con .\instalar.ps1 -Puerto 8080; el favorito sería localhost:8080.
Activar facturación real (no demo) Edita C:\Ligerito\.env: pon FACTURACION_MODO=facturama y las credenciales de Facturama. Ver docs/Guia-Facturacion.md. Por defecto va en demo (timbres de prueba, sin validez fiscal).
Ver errores del servidor Carpeta C:\Ligerito\deploy\windows\logs\.

Solución de problemas

SíntomaCausa / arreglo
La app se queda en /licencia Falta C:\Ligerito\deploy\windows\licencia.token, o el token no empareja con keys.ts. Re-emite en Linux (Fase 1), copia el token y corre dentro de C:\Ligerito: 
npm run lic:instalar -- --archivo deploy\windows\licencia.token
password authentication failed for user "postgres" La contraseña de -PgSuperPassword no es la real de tu PostgreSQL. Vuelve a correr el instalador con la correcta.
P1001 Can't reach database server El instalador ya espera y reintenta 3 veces. Si persiste: abre Servicios de Windows, confirma que el servicio postgresql* esté en ejecución y que escuche en el puerto 5432; luego reintenta.
Unexpected token al correr un .ps1 Es una versión vieja de los scripts (problema de codificación). Usa el ZIP exportado de main actual, que ya trae los scripts corregidos (UTF-8 con BOM).
winget no existe Instala a mano Node 20+ (nodejs.org) y PostgreSQL 16+ (postgresql.org), y vuelve a correr Instalar.bat.
No abre la página / localhost no responde Revisa deploy\windows\logs\, confirma el servicio de PostgreSQL corriendo, y vuelve a correr iniciar.ps1.
Credenciales de fábrica (cámbialas) Admin inicial: admin@posvet.local / admin12345. Base de datos local: usuario posvet / base posvet en 127.0.0.1:5432. La clave de sesión (AUTH_SECRET) se genera única en cada instalación.
